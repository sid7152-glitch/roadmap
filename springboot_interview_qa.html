1 Spring Boot Basics
Q What is the difference between @Controller and @RestController?

@Controller returns a view (HTML page). @RestController returns data directly as JSON/XML — it's a combination of @Controller + @ResponseBody.

In your GitHub Logger — you used @RestController because you're building a REST API that returns JSON commits, not HTML pages.

💡 Remember: @RestController = API. @Controller = web page. You built an API, so @RestController.
Q What does @RequestMapping, @GetMapping, @PostMapping do?

@RequestMapping("/api") — sets the base URL for all endpoints in a controller.

@GetMapping("/commits") — maps HTTP GET requests to a method. Used for fetching data.

@PostMapping("/commits") — maps HTTP POST requests. Used for creating data.

AnnotationHTTP MethodUsed For
@GetMappingGETFetch data
@PostMappingPOSTCreate data
@PutMappingPUTUpdate data
@DeleteMappingDELETEDelete data
💡 Remember: Your /api/commits GET endpoint fetches commits from DB. /api/github GET fetches from GitHub API and saves.
Q What is @Value annotation?

Injects values from application.properties directly into your class fields.

@Value("${api.url}")
private String baseUrl;

In your project — the GitHub API URL was stored in application.properties and injected using @Value so you never hardcode URLs in code.

💡 Remember: You used @Value to inject the GitHub API URL dynamically instead of hardcoding it in GitHubLogService.
Q What is application.properties used for?

Central configuration file for your Spring Boot app. Stores DB credentials, API URLs, server port, JPA settings — anything that shouldn't be hardcoded.

spring.datasource.url=jdbc:postgresql://localhost:5432/github_logger
spring.datasource.username=postgres
api.url=https://api.github.com/users/enter_user/events
spring.jpa.show-sql=true
💡 Remember: You moved GitHub API URL and DB credentials here. Never put these in Java code directly.
2 IoC Container & Dependency Injection
Q What is IoC Container?

IoC = Inversion of Control. Instead of your code creating objects manually using new, Spring creates and manages them for you. The container is a big box that holds all beans and injects them where needed.

Without IoC: CommitRepository repo = new CommitRepository(); // you manage it
With IoC: Spring creates it → puts in container → injects wherever needed
💡 Remember: IoC = Spring manages objects, not you. Hotel analogy — you don't manufacture towels, housekeeping brings them.
Q What is @Autowired and Dependency Injection?

Dependency Injection means Spring automatically provides the objects your class needs. @Autowired is how you request an object from Spring's container.

@Autowired
private CommitRepository commitRepository;
// Spring finds CommitRepository bean → injects here automatically

You never write new CommitRepository(). Spring handles it.

💡 Remember: In GitHubLogService — you @Autowired CommitRepository. Spring injected it automatically. You just used it.
Q What annotations make a class a Spring Bean?
AnnotationUsed OnPurpose
@ServiceService classesBusiness logic
@RepositoryDB classesData access
@ControllerController classesHandle HTTP
@ComponentAny classGeneric bean

Spring scans at startup, finds these annotations, creates objects and puts them in the IoC container.

💡 Remember: GitHubLogService = @Service. CommitRepository = @Repository. GitHubLogController = @RestController.
3 JPA & Hibernate
Q What is JPA and Hibernate?

JPA (Java Persistence API) — a specification/interface that defines how Java objects map to DB tables. It's just rules, not implementation.

Hibernate — the actual implementation of JPA. It generates SQL, manages connections, handles transactions.

Your Code → JPA (interface) → Hibernate (implementation) → PostgreSQL
💡 Remember: JPA is the contract. Hibernate is the worker that actually does the job. Like an interface vs class in Java.
Q What is @Entity and @Table?

@Entity — tells JPA this Java class maps to a DB table.

@Table(name = "commit_records") — specifies which exact table it maps to.

@Entity
@Table(name = "commit_records")
public class CommitModel { ... }
💡 Remember: CommitModel class = commit_records table. @Entity connects them. @Table names the table.
Q What is @Id and @GeneratedValue?

@Id — marks the primary key field.

@GeneratedValue(strategy = GenerationType.IDENTITY) — tells Hibernate to let the DB generate the ID. Maps to PostgreSQL's BIGSERIAL.

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private long id;

When you call save() — Hibernate inserts without ID. Postgres generates it via BIGSERIAL. Hibernate reads it back and sets it on your object.

💡 Remember: BIGSERIAL in Postgres does the job. @GeneratedValue(IDENTITY) just tells Hibernate "step back, DB handles ID."
Q What is @Column?

Maps a Java field to a specific DB column name.

@Column(name = "event_id", unique = true)
private String eventID;

Without @Column — Hibernate maps field name directly. With it — you control the exact column name and constraints like unique, nullable.

Q How does Hibernate generate and execute a query?
commitRepository.save(commit)
↓ Hibernate reads @Entity, @Table, @Column annotations
↓ Builds: INSERT INTO commit_records (event_id, commit_head...) VALUES (?, ?, ...)
↓ JDBC replaces ? with actual values (Prepared Statement)
↓ PostgreSQL executes, BIGSERIAL generates ID
↓ Hibernate reads generated ID back → sets on your object
💡 Remember: show-sql=true in application.properties shows you exactly what SQL Hibernate generates. Use it for debugging.
Q What is ddl-auto and what are the options?

💡 Remember: You used validate because you created tables manually in pgAdmin. Spring just verifies the mapping is correct.
4 Spring Data JPA
Q What is JpaRepository?

A Spring Data interface that gives you ready-made DB operations without writing SQL or implementation code.

@Repository
public interface CommitRepository extends JpaRepository<CommitModel, Long> { }

JpaRepository<T1, T2> — T1 is the Entity class, T2 is the primary key type.

Built-in methods you get for free: save(), saveAll(), findAll(), findById(), deleteById(), count()

💡 Remember: Zero SQL written. Spring generates implementation at runtime using proxy pattern. Just extend the interface.
Q What are Derived Query Methods?

Spring Data generates SQL automatically just from the method name. Follow the naming convention and Spring does the rest.

MethodGenerated SQLReturns
existsByEventID(id)SELECT COUNT(*) > 0 WHERE event_id = ?boolean
findByRepository(repo)SELECT * WHERE repository = ?List
countByCreatedAt(date)SELECT COUNT(*) WHERE created_at = ?long
deleteByEventID(id)DELETE WHERE event_id = ?void
💡 Remember: You used existsByEventID() to prevent duplicate entries before saveAll(). Spring generated the EXISTS query automatically from the method name.
Q What is the difference between findBy, existsBy, countBy, deleteBy?
KeywordPurposeReturns
findByFetch matching recordsList or Object
existsByCheck if record existsboolean
countByCount matching recordslong
deleteByDelete matching recordsvoid

⚠️ Note: It's existsBy not existBy — missing the 's' will throw a "No property found" error.

5 Exception Handling
Q What is Global Exception Handling and why do we need it?

Without it — when something fails, Spring dumps an ugly stack trace to the client. With it — you intercept exceptions and return a clean, structured JSON error response.

Without: 500 Internal Server Error + java.lang.RuntimeException stack trace dump

With: { "timestamp": "...", "status": 500, "error": "GitHub API failed with status: 403" }
Q What is @RestControllerAdvice vs @RestController?
@RestController@RestControllerAdvice
PurposeHandle HTTP requestsHandle exceptions
ScopeSingle controllerALL controllers
Triggered byHTTP requestException thrown
Contains@GetMapping etc@ExceptionHandler methods
💡 Remember: @RestController = main chef. @RestControllerAdvice = manager at the exit. Anything goes wrong anywhere — manager intercepts it.
Q What is ResponseEntity and why use generics with it?

ResponseEntity gives you full control over the HTTP response — status code, headers, and body together.

return ResponseEntity
    .status(HttpStatus.INTERNAL_SERVER_ERROR)  // you control status
    .body(error);                               // you control body

Generics ResponseEntity<ErrorResponse> — tells Spring the body will be of type ErrorResponse. Provides compile-time type safety. Wrong object in body = compiler error immediately.

💡 Remember: ResponseEntity = envelope. You control what's inside. Generics = label on envelope saying what's inside. Output is same but generics prevent wrong data being sent.
Q What is a custom exception and why use it over RuntimeException?

A custom exception gives a specific, meaningful name to the error instead of a generic one.

public class GitHubAPIException extends RuntimeException {
    public GitHubAPIException(String message) {
        super(message);
    }
}

RuntimeException = "something went wrong somewhere." GitHubAPIException = "the GitHub API specifically failed." Anyone reading the code immediately understands what happened.

💡 Remember: Custom exception = specific name for a specific problem. Makes code readable and exception handlers more precise.
Q What is the full exception handling flow?
GitHub API returns 403
↓ Service throws GitHubAPIException("GitHub API failed: 403")
↓ Exception bubbles through Controller (no handler there)
↓ @RestControllerAdvice intercepts
↓ @ExceptionHandler(GitHubAPIException.class) matches
↓ ErrorResponse DTO created with timestamp, status, message
↓ ResponseEntity wraps it with HTTP 500
↓ Clean JSON sent to client
6 Java 8+ Features
Q What is a Functional Interface?

An interface with exactly ONE abstract method. Used with lambda expressions.

@FunctionalInterface
public interface MyFunction {
    void execute(); // only one abstract method
}

Built-in examples: Runnable, Callable, Comparator, Predicate, Function

💡 Remember: One method = Functional Interface. That's the contract. @FunctionalInterface annotation enforces this rule at compile time.
Q What are the three ways to implement a Functional Interface?
// 1. Anonymous class (old way)
MyFunction f = new MyFunction() {
    public void execute() { System.out.println("Hello"); }
};

// 2. Lambda (clean way)
MyFunction f = () -> System.out.println("Hello");

// 3. Method reference (shortest)
MyFunction f = MyClass::myMethod;
Q What are Streams? Explain one method.

Streams process collections in a pipeline without modifying the original data. Introduced in Java 8.

// filter() — keeps elements matching condition
List<CommitModel> newCommits = commits.stream()
    .filter(c -> !commitRepository.existsByEventID(c.getEventID()))
    .collect(Collectors.toList());

Common stream methods: filter(), map(), reduce(), sorted(), forEach(), collect()

💡 Remember: You used streams in GitHubLogService to filter out duplicate commits before saving. filter() is the exact method you used.
Q What is Optional class?

A wrapper class to handle null values safely and avoid NullPointerException.

Optional<String> name = Optional.of("Siddharth");
name.isPresent();         // true
name.get();               // "Siddharth"
name.orElse("Unknown"); // returns value or default if empty
💡 Remember: Optional = box that may or may not contain a value. orElse() is your safety net — gives a default if box is empty.
7 Microservices
Q How do Microservices communicate with each other?

Two ways:

Synchronous — REST API calls over HTTP. One service calls another directly and waits for response. Tools: RestTemplate, WebClient, Feign Client.

Asynchronous — Message queues. One service publishes a message, another consumes it independently. No waiting. Tools: Kafka, RabbitMQ, IBM MQ.

TypeToolsUse When
SynchronousRestTemplate, WebClient, FeignImmediate response needed
AsynchronousKafka, RabbitMQ, IBM MQDecoupled, high volume
💡 Remember: IBM MQ at Accenture = asynchronous messaging. Kafka = modern version of same concept. You're already familiar with the idea.
Q What are Containers in cloud context?

Docker containers — lightweight isolated environments. Your app + all its dependencies packaged together. Runs the same on any machine.

Kubernetes — manages and orchestrates multiple containers. Auto scaling, load balancing, health checks.

Your Spring Boot App → Docker Image → Docker Container → Kubernetes Pod → Cloud (GCP/AWS)
💡 Remember: At Accenture you check pod logs — those pods are Kubernetes containers running the application. You're already seeing this in production.
Q What is Spring Security?

A framework that handles Authentication and Authorization in Spring Boot.

Authentication — Who are you? (Login, JWT token verification)

Authorization — What can you access? (Role based access — ADMIN, USER etc)

Commonly implemented with JWT tokens where user logs in, gets a token, and sends it with every request.

8 Bean Lifecycle
Q What is the lifecycle of a Spring Bean?
1. Instantiation — Spring creates the object
↓
2. Dependency Injection — @Autowired fields are populated
↓
3. @PostConstruct — runs after bean is fully initialized
↓
4. Bean Ready — available for use in application
↓
5. @PreDestroy — runs before bean is destroyed
↓
6. Destroyed — bean removed from container 
@PostConstruct
public void init() {
    // runs after GitHubLogService is fully created and injected
}

@PreDestroy
public void cleanup() {
    // runs before Spring shuts down
}
💡 Remember: @PostConstruct = "I'm ready, do setup." @PreDestroy = "I'm shutting down, do cleanup." Like constructor and destructor but Spring managed.
Q How to add a custom dependency in pom.xml?
<dependency>
    <groupId>org.postgresql</groupId>       <!-- organisation -->
    <artifactId>postgresql</artifactId>   <!-- library name -->
    <version>42.7.10</version>           <!-- specific version -->
    <scope>runtime</scope>               <!-- when to include -->
</dependency>
ScopeMeaning
compileAvailable everywhere (default)
runtimeOnly needed at runtime, not compile time
testOnly for tests
💡 Remember: PostgreSQL driver is runtime scope — you don't reference it in code, Spring uses it behind the scenes to connect to DB.

Q Walk me through your exception handling implementation

Built a three-layer exception handling architecture in the GitHub Logger project:

GitHubAPIException — custom exception extending RuntimeException. Thrown when GitHub API returns non-200 status or connection fails. Gives meaningful name to the error.

ErrorResponse DTO — POJO with timestamp, status, error fields. Jackson serializes it to clean JSON automatically.

GlobalExceptionHandler — @RestControllerAdvice intercepts all escaping exceptions. Two handlers: GitHubAPIException → 500, Exception → 400 fallback.

Result: {"timestamp":"...","status":500,"error":"GitHub API failed with status: 404"}
💡 You tested this: Hitting /api/github?devProfile=invaliduser999999 returned clean JSON error with status 500. Stack trace gone completely.
